Executive Summary

Project Overview

What MediSync Is

MediSync is a web-based healthcare coordination platform that connects hospitals, doctors, patients, and pharmacies through a centralized digital prescription workflow.

Core Value Drivers

  • Digital prescription transmission from doctors to verified pharmacies.
  • Digital prescription verification using QR-based validation.
  • Centralized patient medical history and PDF export.
  • System audit logging for operational transparency and governance.
Healthcare Gaps

Problem Statement

Gap 01

Paper Prescription Risks

Traditional handwritten and printed prescriptions can increase the risk of alteration, duplication, and dispensing errors.

Gap 02

Fragmented Pharmacy Workflows

Manual verification between pharmacies and prescribing providers can introduce delays and operational bottlenecks.

Gap 03

Fragmented Patient Records

Patients may lack convenient access to centralized digital records of prescriptions, medications, and prescribing information.

The Innovation

Proposed Solution

1. Problem
Manual & Vulnerable

Paper prescription delays, error-prone dispensing, unverified pharmacy interactions.

2. Solution
MediSync Platform

Role-based authentication, digital prescription transmission, QR-based verification, and centralized record management.

3. Outcome
Verified Digital Workflow

Fast digital prescription workflow, audit traceability, traceable and verifiable prescription lifecycle.

Strategic Alignment

Core System Objectives

1. Fast Digital Prescription Sync

Deliver prescriptions to verified pharmacies through a fast digital workflow.

2. Role-Based Access Control

Enforce role-based access controls across Admin, Hospital, Doctor, Pharmacy, and Patient portals.

3. Application Security

Implement JWT-based authentication, password hashing, rate limiting, and request validation.

4. Verification Governance

Implement mandatory Admin approval queues for new Hospital and Pharmacy registrants.

5. Audit Logging

Maintain system audit trails for prescription generation, link requests, and dispensing events.

6. Digital Health PDF Exports

Generate downloadable, standardized prescription documents for offline access and record keeping.

User Ecology

Multi-Role User Personas

Role 1

System Admin

Oversees platform governance, approves hospital & pharmacy accounts, monitors system audit logs.

Role 2

Doctor

Creates digital prescriptions, links patient records, assigns consulting rooms and medical instructions.

Role 3

Pharmacy Staff

Accesses pending prescription queues, verifies dosage details, and marks prescriptions as DISPENSED.

Role 4

Patient

Views assigned doctor details, tracks prescription status, downloads PDF records, scans QR verification.

Digital Prescription Engine

Dynamic medicine addition with dosage, frequency, and duration tracking.

Process Flow

End-to-End System Workflow

Step 1

Consultation

Doctor creates digital prescription in Doctor Portal.

Step 2

API Processing

Express API validates the request, stores the prescription, and records the corresponding audit event.

Step 3

Pharmacy Queue

Prescription appears in near-real-time on Pharmacy Queue.

Step 4

Fulfillment

Pharmacy dispenses medication; status updates to DISPENSED across relevant views.

Data Protection

Application Security Measures

HTTP-Only Cookie Auth

HTTP-only cookies reduce client-side JavaScript access to authentication tokens and help mitigate token theft through certain XSS scenarios.

BcryptJS Password Hashing

Passwords are hashed using bcryptjs before storage in the database.

Rate Limiting & Validation

Rate limiting helps protect authentication endpoints against repeated or brute-force login attempts.

Engineering Insights

Technical Challenges & Solutions

Challenge 1

Cross-Role State Sync

Problem: Ensuring prescriptions created by doctors update in pharmacy queues without full manual page reloads.
Solution: Polling and structured REST API refetching were used to keep prescription status synchronized across relevant views.

Challenge 2

Secure Multi-Role Access Control

Problem: Preventing unauthorized access to patient data across different roles.
Solution: Enforced server-side JWT verification middleware on API endpoints checking user role and account approval state.
